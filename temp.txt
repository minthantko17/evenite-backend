M-XX-001
buildFormFieldStats(
fields: FieldStatsField[],
rows: (FieldStatsRow & { formFieldId: string })[],
): AnalyticsFieldStatsDto[]
Description
Summarizes all the stored answers of a form into one statistics entry per form field. This is a pure function with no database access.
The method first groups the answer rows by their formFieldId. It then goes through the fields in the order they were given, and builds each field's statistics from the rows of that field only (an empty list if nobody answered it). Because every field is mapped, a field with no answers still appears in the result.
Parameters
fields: FieldStatsField[] – The fields of the form, each with its ID, label, type, and defined options.
rows: (FieldStatsRow & { formFieldId: string })[] – The stored answers of the form's responses, each tagged with the ID of the field it answers.
Returns
AnalyticsFieldStatsDto[] – One statistics entry per field, in the same order as fields. [Appendix B-XX-004]

M-XX-002
buildFieldStats(
 field: FieldStatsField,
 rows: FieldStatsRow[],
): AnalyticsFieldStatsDto
Description
Summarizes the stored answers of a single form field, in a shape that depends on the field's type. This is a pure function with no database access.
For CHOICE and CHECKBOX fields, the method starts a counter of 0 for every defined option, so unchosen options are still shown. It then skips rows whose selected values are empty, counts every other row as answered, and adds 1 to the counter of each selected value (a stored value that is not a defined option gets its own counter). For NUMBER and RATING fields, it collects the numeric values of the rows that have one, and returns the answered count together with the average (rounded to 2 decimals), minimum, and maximum, which are null when nobody answered. RATING fields also get a distribution, which lists only the values that actually occurred, in ascending order, since the rating scale is not enforced anywhere. For DATE fields, only the number of rows that have a date is returned. For TEXT and TEXTAREA fields (and any other type), only the number of rows whose text is not empty after trimming is returned, and the text content itself is never aggregated.
Parameters
field: FieldStatsField – The form field to summarize, with its ID, label, type, and defined options.
rows: FieldStatsRow[] – The stored answers of this field only.
Returns
AnalyticsFieldStatsDto – The field's ID, label, type, and answered count, plus the type-specific properties described above (options, average, min, max, distribution). [Appendix B-XX-004]

AnalyticsService
M-XX-023
getEventAnalytics(
 eventId: string,
 organizerProfileId: string,
 range: AnalyticsRange,
): Promise<ReturnAnalyticsDto>
Description
Builds the full analytics dashboard payload for one event, so an organizer can see registration, check-in, and feedback figures in a single response.
First, the method checks that the caller owns the event, and then that the event exists. It then works out the timeline end, which is the earlier of the current time and the event's end time (the event's endAt if set, or its startAt plus 24 hours if not, or the current time for a draft with no dates). Next, it runs the following queries at the same time: the overview counts, the check-in counts per method, the registration timeline, the check-in timeline, and the answer data of the registration form and the feedback form. Each timeline is built according to range: '24h' gives 24 hourly buckets, '7d' gives 7 daily buckets, '30d' gives 30 daily buckets, and 'all' covers everything from the first activity up to the timeline end. Daily buckets start at midnight in the Asia/Bangkok time zone. The registration answers are summarized per form field, and are an empty list if the event has no registration form. The feedback section is null if the event has no feedback form. Otherwise it includes the response count, a response rate calculated against the number of checked-in participants (since only attendees can respond), and the summarized answers per field.
In the overview, notCheckedIn is registered minus checkedIn (never below 0), attendanceRate is checkedIn divided by registered, and registerRate is registered divided by the event's seat limit. A rate is null when its denominator is 0 or missing.
Parameters
eventId: string – The unique identifier of the event whose analytics are being requested.
organizerProfileId: string – The profile ID of the organizer making the request; must be the owner of the event.
range: AnalyticsRange – The time window of the timelines: '24h', '7d', '30d', or 'all'. [Appendix B-XX-001]
Returns
Promise<ReturnAnalyticsDto> – The generation time, the range and time zone used, the overview figures, the check-in and registration timelines, the check-in counts per method, the registration answer summaries, and the feedback summary (or null). [Appendix B-XX-002]
Throws
EventNotFoundException – Thrown when no event exists for the given eventId.
ForbiddenException – Thrown when the caller is not the organizer who owns the event ("You do not have permission to edit this event.").

M-XX-024
private buildTimeline(
 source: TimelineSource,
 range: AnalyticsRange,
 timelineEnd: Date,
): Promise<AnalyticsTimelineDto>
Description
Builds the timeline of one activity stream (registrations or check-ins) for the chosen range.
For the 'all' range, the method asks the source for its earliest activity before timelineEnd. If there is none, an empty timeline is returned. Otherwise, the bucket size is picked from the span between that first activity and the timeline end (hourly up to 48 hours, daily beyond), and the bucket starts run from the bucket of the first activity to the last bucket. If that gives more than 366 buckets, only the most recent 366 are kept. For the other ranges, the bucket size is hourly for '24h' and daily otherwise, and the bucket starts are the fixed number of buckets (24, 7, or 30) ending at the timeline end. Once the bucket starts are known, the method fetches, at the same time, the timestamps of the activity inside the timeline and the number of activities before the first bucket, and fills the timeline from them, so the running total stays correct even when older buckets are cut off.
Parameters
source: TimelineSource – How this stream reads its activity: its timestamps in a window, its count before a moment, and its earliest activity.
range: AnalyticsRange – The time window of the timeline: '24h', '7d', '30d', or 'all'. [Appendix B-XX-001]
timelineEnd: Date – The exclusive end of the timeline.
Returns
Promise<AnalyticsTimelineDto> – The timeline with one point per bucket. [Appendix B-XX-003]

Description
